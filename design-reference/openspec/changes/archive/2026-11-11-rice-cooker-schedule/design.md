# Design: 极简列表与步进对齐

## 1. 模型选择：从「算一个结果」到「列多个结果」

| | 配置式 | 列表式（采用） |
|---|---|---|
| 工作日 / 周末 | 两套规则 + 按星期切换 | 列表里同时摆 `07:30 / 08:00 / 09:30`，看对应行即可 |
| 今天临时改 | 临时改控件，且不污染记忆 | 看另一行；没有就加一行 |
| 不上班 / 跳过 | 跳过今天控件 | 不按就行；长期不用就左滑删 |
| 记住上次选择 | 需要状态 | 所有选项一直并列在眼前 |

**结论**：用户每天真正的动作只有「看一眼、按一个数」。凡是让这个动作多一步的东西都删掉。

**意外收获**：每行取「该时刻下一次出现」，预约值天然落在 `step ~ 24 小时`。早期方案里那整套「超 24 小时警示 / 建议回来设置时刻 / 到点提醒」不是被砍掉，而是**失去了存在前提**。

## 2. 计算模型

```
N       = 当前时刻向下取整到分钟（分钟级，整分钟内稳定）
D       = 该行时刻下一次出现：今天剩余 ≥ step 取今天，否则顺延到明天
maxSet  = floor(1440 / step) × step
T       = min( floor((D − N) / step) × step, maxSet )
实际完成 = N + T
```

- **不减烹饪时长**：客服确认预约是「几小时后煮好」，机器自行倒推开火时刻。这是整个项目最容易搞反的一条。
- **向下取整**：`N + T ≤ D`，饭只会提前煮好进保温，绝不迟到。步进整除 1440 时最多提前 `step − 1` 分钟（默认 9 分钟，已确认可接受）。
- **maxSet 的必要性**：自定义步进不整除 1440（如 25 分）时，顺延到明天后 `D − N` 略超 1440，直接取整会得到 `24 小时 10 分` 这种机器按不进去的值。`maxSet = 1425` 收敛后仍可按、仍不迟到，只是提前更多，由右侧「实际完成」小字如实呈现。
- **取整跳变**：21:37 是「10 小时 20 分 / 实际 07:57」，21:41 变「10 小时 10 分 / 实际 07:51」。这不是算错——21:41 再按 10:20 会 08:01 才煮好。改成「最接近」能削掉一半跳变，但会允许迟到 4~5 分钟，对固定出门时间更不友好。

## 3. 为什么步进是唯一保留的设置

步进满足三个条件，与其他被砍的配置不同：

1. 会改变**所有行**的取值（10 分 → 10:20，30 分 → 10:00）；
2. 不同机型不一样，写死在代码里不踏实；
3. 一次设定长期不变，属于「记住不变量」。

实现为底部说明行里一个 11px 灰字链，展开一排预设 + 一个自定义输入框（`10–240` 整数分钟）。主界面可见控件仍只有「+ 添加时间」一个按钮，没有设置页、没有第二个常驻面板。

**没有连带加「取整方向」设置**：那会变成第二个需要用户决策的参数；提前 9 分钟已确认可接受，先按默认跑。

## 4. 信息层级判断（回应「预期完成时间要不要和预约时间一样大」）

**不调到一样大，适度调大到 20px / 600 / 主文字色**。三个理由：

1. **一行只该有一个主角**：左边是要执行的值，右边是帮你认行的标签。两串数字等大后会变成并列对比，用户多一次「该按哪个」的判断，`08:00` 甚至容易被误读成「8 小时」。
2. **活的该比死的重**：左边每分钟在变且要按进机器，右边永远不变，是锚点。视觉权重跟着动作走。
3. **16px 确实偏小**：睡前暗光单手瞄一眼会吃力，所以提升而非维持。

再叠 10.5px 灰字放实际完成时间，右侧形成「20px 主信息 → 11px 日期 → 10.5px 实际」三级，信息变多反而更干净。橙色只留给要按的那个数。

## 5. 交互与持久化

| 动作 | 交互 | 保存 |
|---|---|---|
| 看 | 打开即出结果，每分钟更新 | 无需操作 |
| 加 | 时间选择器，选完即插入并排序 | 自动落盘 |
| 删 | 左滑露出「删除」，点一下即删 | 自动落盘 |
| 设步进 | 预设点选 / 自定义输入后点「使用」 | 自动落盘 |

删错不做二次确认、不做撤销，因为重加只要 2 秒。重复时刻自动忽略，删空显示空状态。

## 6. Known Trade-offs

1. **不校验 `T < C`**：界面不知道在煮什么，07:55 看 08:00 行仍会显示「5 分钟」，但煮 30 分钟的饭其实来不及，需用户自行判断。
2. **不做设置后锁定**：列表是「扫一眼、按完即走」，锁定还得决定锁哪行，成本大于收益；按完若停留页面，数字会继续变。

两者都只在边缘场景出现，日常睡前设置不受影响。真卡住了各加一行提示即可，不引入整套控件。

## 7. 明确不做

多设备/多人、云端同步、真实推送、联网联动、菜谱库、历史统计、工作日/周末分档、焖饭余量、到点提醒、设置后锁定、复制、主题按钮、重置、确认弹窗、撤销、上限警示。
