# Project Context

## Purpose

「电饭煲预约助手」是一个单页工具：把「睡前该把电饭煲预约到几小时几分」变成一张可扫视的实时列表，用户照抄左边的数字即可，不做任何每日配置。

核心洞察：产品价值不在计算，而在**把配置问题换成扫视问题**。多个预期完成时刻并列显示，用户靠右边认行、靠左边取值；工作日、周末、临时改时间、跳过某天等例外，全部由「看另一行 / 加一行 / 删一行」吸收。

## Domain Context

- 电饭煲的「预约」是**几小时后煮好**，不是几小时后开始煮。机器会根据烹饪时长自行倒推开火时刻，因此**烹煮时长不参与本工具的计算**。
- 用户说的「煮 30 分钟」与界面上的「预约 10 小时 20 分」是两个不同概念，文案必须硬区分。
- 使用场景集中在睡前（20:00–24:00）与早晨出门前，单次交互目标 ≤ 10 秒，常在暗光、单手条件下完成。
- 出门时间级别固定，不需要每天重复设置。

## Confirmed External Facts (from customer support)

| 项 | 值 |
|---|---|
| 预约语义 | 几小时后煮好，机器自行倒推开始时刻 |
| 最小步进 | 10 分钟 |
| 最大预约 | 24 小时 |
| 输入方式 | 仅倒计时 |
| 提前进保温 | 最多 9 分钟，已确认可接受 |

## Constraints

- 纯静态单页 HTML/CSS/JS，无构建步骤、无框架、无后端、无网络请求、无账号、无上传。
- 数据仅存 `localStorage`；时间以设备系统时钟为准（不校时）。
- 单屏移动端优先（375×667 起），PC 端居中窄栏；20:00–07:00 自动深色。
- 主界面可见控件**只有一个**「+ 添加时间」按钮；步进设置是底部说明行里的一个文字链，属一次性配置。
- 改动即时落盘，**不设保存按钮、确认弹窗、撤销**。
- 视觉层级：左侧预约值 27px 橙色为唯一主角；右侧预期时刻 20px 主文字色为识别标签；实际完成时间 10.5px 灰字为补充信息。

## Tech Stack

- HTML5 + 原生 CSS（CSS 变量切换深浅色）+ 原生 ES2020 JavaScript，无第三方依赖。
- `localStorage` 键 `rice_cooker_v5`，结构 `{ targets: string[], stepMinutes: number }`；兼容迁移 `rice_cooker_v4` / `rice_cooker_v3`。
- 验收用 Playwright 无头浏览器 + URL 参数 `?sim=<ISO datetime>` 注入模拟时间，界面上无演示控件。
- 公开仓库：`wzzhuz/rice-cooker-schedule`。
- 仓库侧 CI：`.github/workflows/build.yml` + `.github/scripts/build.py`，push/PR 自动做文件校验、JS 语法检查、26 项浏览器验收、重生成预览、组装 `dist/`、打包并上传 artifact；只申请 `contents: read`，不依赖 Pages 权限。**原型本身仍无构建步骤、无依赖**，CI 只是验收与打包流水线。

## Key Decisions

| 决策 | 理由 |
|---|---|
| 列表模型，而非「配置目标时刻 + 算一个结果」 | 例外场景无需额外控件，界面复杂度与使用成本最低 |
| 每行取「该时刻下一次出现」 | `T ≤ 24 小时` 恒成立，上限警示/回来提醒失去存在前提 |
| 按步进向下取整 + `maxSet` 兜底 | 绝不迟到；同时保证自定义步进不整除 1440 时仍可按 |
| 不提供取整方向设置 | 避免第二个用户决策；提前 9 分钟已确认可接受 |
| 预期时刻调大到 20px 但不与预约值等大 | 一行只该有一个主角，避免「该按哪个」的误判 |
| 不显示烹煮档、不加设置后锁定 | C 不进公式；锁定还需决定锁哪行，成本大于收益 |

## Out of Scope

多设备/多人配置、云端同步、真实推送、与电饭煲联网联动、菜谱库、历史统计、工作日/周末分档规则、焖饭余量、到点提醒、设置后锁定、复制按钮、主题切换按钮、重置按钮。

## Known Trade-offs

1. 不校验 `T < C`：剩余 5 分钟却要煮 30 分钟的饭时，界面仍会给出「5 分钟」，需用户自行判断。
2. 不做设置后锁定：按完电饭煲若仍停留页面，左侧数字会继续递减。

两者都只在边缘场景出现，日常睡前设置不受影响；若日后需处理，各加一行提示即可，不引入整套控件。
